# セキュリティ概要：Kintai

🌐 [English](../security-overview.md) · [Français](security-overview.fr.md) · **日本語**

## 🏗 アーキテクチャによるセキュリティ
- **テナント分離：** 「オーナーごとに1インスタンス」というモデルにより、テナント間のデータ漏洩を設計段階で防止します。
- **依存関係の最小化：** 外部パッケージを減らすことで攻撃対象領域を最小化します。
- **物理的分離：** データベースは論理的または物理的に分離されており、単一データベースが侵害された場合の影響を抑えます。

## 🔐 主なセキュリティ対策
- **認証：** Webはセッションベース認証、APIはBearerトークン認証。
- **認可：** 店舗ごとの詳細なロールベースアクセス制御（RBAC）（管理者・マネージャー・スタッフ）。
- **暗号化：** 安全なパスワードハッシュ化（Bcrypt/Argon2）と、機微な設定情報の暗号化。
- **CSRF・XSS対策：** CSRF保護のための組み込みミドルウェアと、ビュー層での厳格なエスケープ処理。
- **監査ログ：** シフト変更、設定変更、ユーザー作成などすべての重要な操作が、ユーザーID・日時・IPアドレスとともに記録されます。

## 📡 ネットワーク・インフラ
- **SSL/TLS：** すべてのSaaSインスタンスでHTTPSを必須化。
- **セキュリティヘッダー：** HSTS、Content Security Policy（CSP）、X-Frame-Optionsをミドルウェアでデフォルト有効化。
- **Content Security Policy：** スクリプトは Kintai 自身が配信するもの、またはリクエストごとの nonce を持つものだけが実行されます（`script-src 'self' 'nonce-…'`、`'unsafe-inline'` なし）。XSS の脆弱性から注入されたスクリプトや `onclick=` はブラウザにブロックされます。ビューはインライン handler の代わりに、`csp-actions.js` が処理する宣言的な `data-*` 属性を使います。バンドルも同様にしてください（[バンドルの作り方](creating-a-bundle.ja.md#content-security-policyインラインスクリプトは使えません) を参照）。
- **レートリミット：** ログインおよび機微なAPIエンドポイントをブルートフォース攻撃から保護します。

## 🛠 シークレット管理
- **インスタンスごとのシークレット：** プロビジョニング時にSaaSオーケストレーターが管理します。
- **環境分離：** シークレットはバージョン管理には一切コミットされず、分離された `.env` ファイルや安全なシークレットストア（例：Vault）に保管されます。

## ⚖ コンプライアンス
- **GDPR対応：** データの可搬性、忘れられる権利、物理的分離により、SaaSにおけるGDPR対応が容易になります。
- **各国の労働法：** 現地の規制に準拠した、労働時間・休憩の厳密な記録をアーキテクチャレベルでサポートします。
