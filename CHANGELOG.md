# Changelog

🌐 **English** · [Français](docs/i18n/CHANGELOG.fr.md) · [日本語](docs/i18n/CHANGELOG.ja.md)

All notable changes to Kintai are documented here.

## [Unreleased]

### Added
- New Owner settings tab, **Bundles** (`/admin/bundles`), to enable/disable each installed bundle for the whole instance — previously only possible by hand-editing `config/license.php`. The toggle is stored in `app_settings` (`enabled_bundles`) via `LicenseServiceProvider`, which now reads that setting first and falls back to `config/license.php` when unset (so existing deployments keep working unchanged). The per-store feature toggle (store edit page) now also lists `photos` and only proposes bundle-backed features (`messages`, `daily_reports`, `photos`) when the corresponding bundle is enabled instance-wide; `StorePhotoController` now actually enforces the per-store `photos` toggle (it previously had no such check, unlike the employee-facing time off/swap/open-shift/messaging flows).
- Bundles are no longer hardcoded in a registry: `BundleDiscoveryService` scans `src/Bundles/*/` at boot and auto-detects any `{Name}\{Name}Bundle` class extending `Bundle`, replacing the removed `config/bundles.php`. Third-party bundles just need to be dropped in `src/Bundles/` (same PSR-4 convention) to show up on `/admin/bundles` — no core code change needed. A new `config/official-bundles.php` lists the slugs of bundles actually developed and maintained by the Kintai project; anything discovered but absent from that list is flagged "third-party" on `/admin/bundles` with a warning that it isn't maintained by the main project. `Bundle` gained optional `getLabel()`/`getDescription()` methods for this listing (overridden by `DailyReportBundle`/`MessagingBundle`, default to a humanized slug otherwise). `config/official-bundles.php` was also missing `store-photos` since its own extraction; fixed here.
- Time off management (employee submission, admin approve/refuse/create-on-behalf, `/api/v1/timeoff-requests`) moved into a new `timeoff` bundle (`src/Bundles/TimeOff/`). Unlike other bundles, `TimeoffRequestRepositoryInterface` stays registered in Core (`RepositoryServiceProvider`) rather than moving into the bundle: `StoreStatsService`, `ShiftService`, `AdminShiftController`, `IcalController`, and `EmployeeController`'s dashboard all read time-off data for calculations that must keep working even when this bundle is disabled — only the dedicated management UI and its routes are bundle-only. `EmployeeController`'s `assertFeature()` store-level feature check was extracted into a reusable `HasStoreFeatureCheck` trait, shared with the bundle's new `EmployeeTimeoffController`. Enabled by default, so no behavior change for existing deployments.

### Changed
- Store photos (weekly store-condition photo submissions, retention/cleanup settings) moved out of Core into a new `store-photos` bundle (`src/Bundles/StorePhoto/`), following the same pattern as the Messaging and Daily Report bundles. `StorePhotoController`, its routes, and its views moved under the bundle; `StorePhotoRepositoryInterface` is now registered by the bundle instead of the core `RepositoryServiceProvider`. Enabled by default (`config/license.php`), so there is no behavior change unless a deployment explicitly disables it. First step of the broader effort to shrink Core down to Shift/User/Store and move every optional feature (time off, shift swaps, open shifts, HR reports, ...) into its own toggleable bundle.
- Shift swap management (employee propose/accept/refuse/cancel, admin apply-immediately/approve/refuse, `/api/v1/shift-swap-requests`) moved into a new `shift-swap` bundle (`src/Bundles/ShiftSwap/`). Like `timeoff`, `ShiftSwapRequestRepositoryInterface` stays registered in Core (`RepositoryServiceProvider`) instead of moving into the bundle: `StoreStatsService`, `HomeController`, and `EmployeeController`'s dashboard all read swap data for calculations that must keep working even when this bundle is disabled — only the dedicated management UI and its routes are bundle-only. `EmployeeController`'s two swap-only helpers (`buildUsersMap()`/`buildShiftsMap()`) moved into the bundle's new `EmployeeSwapController` along with the swap methods, reusing the `HasStoreFeatureCheck` trait. Enabled by default, so no behavior change for existing deployments. Also fixes `config/official-bundles.php`, which was still missing `store-photos`.
- Moved all translated documents (`*.fr.md`, `*.ja.md`) into `docs/i18n/`, including the ones formerly living next to their English source in `docs/`. `docs/security.md` was renamed to `docs/security-overview.md` to avoid a case-insensitive filename clash with the root `SECURITY.md` translations. `scripts/check-translations.php` now always looks for translations under `docs/i18n/` regardless of the source document's folder.
- `docs/database.md` updated to reflect the actual `illuminate/database` version (^13.19, not ^11.0) and clarified that the `Language`/`Translation` repository interfaces are now bound to JSON-file-backed implementations, not Eloquent — their `Database*Repository` counterparts are unused dead code left over from before the i18n JSON migration.
- Split the combined "Backups & Updates" settings tab into two separate tabs, **Backups** and **Updates**. The GitHub self-update UI (version, pending migrations, one-click update with progress) now lives on its own page at `/admin/update`, while `/admin/backup` only handles create/restore/delete. The underlying `POST /admin/backup/update(/stream)` and `/migrate` routes moved to `/admin/update/apply`, `/admin/update/stream`, and `/admin/update/migrate`.
- `UpdateService::getCurrentVersion()` now reads the installed version straight from `config/app.php` (bumped on each release and synced by the self-update process) instead of tracking a separate `storage/app/version.json` `version` field. That file still records `installed_at`/`updated_at`/`duration_seconds`, but is no longer the source of truth for the app version.
- `docs/vision.md` reworked: target audience is now framed by sector (retail, hospitality, and other shift-based multi-site verticals) instead of a Japan-first / global-SME split; updated the closing tagline.
- `docs/business-model.md` reworked: the pricing bullet list is now a Community / Pro / Business / Enterprise table, with paid tiers clarified as controlling what's activated and supported by default on the managed SaaS — not gating what exists in the open-source codebase; direct-sales messaging no longer singles out Japan.
- `docs/architecture.md`: dropped the `(Planned)` Webhooks line (no longer on the roadmap); noted that the HR reports (hiring/resignation/salary) and store photos currently live in Core rather than as bundles, flagged as candidates for a future bundle migration.
- `docs/security-overview.md`: generalized "Japanese Labor Law" to "Local Labor Law" to match the new sector-based positioning.
- `docs/i18n/database.fr.md` and `docs/i18n/database.ja.md` brought back in sync with the English source (Eloquent version, dead-code note for the `Language`/`Translation` repositories).

### Added
- Wired up the orphaned `backup` cron job: `CronRunner`, `AutoValidateJob`, and `BackupJob` were fully implemented but never registered or reachable from any route. `AppServiceProvider` now builds a `CronRunner` singleton with both jobs registered, and a new `GET /cron/run/{job}` route (token-scoped via the `cron_tokens` table, `Authorization: Bearer` or `?token=`) exposes them. `scripts/create-cron-token.php` issues the per-job tokens this endpoint needs.

### Fixed
- The installer no longer fails with "Database file at path [...] does not exist." when `storage/app/database.sqlite` is missing (e.g. after an incomplete or deleted previous install) — the file and its directory are now created automatically before the framework boots.
- `docs/releasing.md` (and its FR/JA translations) still pointed to `/admin/backup` for the self-update UI; fixed to `/admin/update`, matching the settings-tab split.
- **Security:** the Messaging and DailyReport bundles' `/api/v1/*` routes were registered without `ApiAuthMiddleware`, unlike every other `/api/v1/*` endpoint — they were reachable without a Bearer token even though their controllers assumed an authenticated `auth_user`. Both bundles' `routes.php` now wrap their API routes in the same protected group as the core API.
- **Critical:** shift swap requests were completely broken — creating, accepting, or refusing a swap wrote/read the columns `target_id`/`peer_accepted_at`, which don't exist in the `shift_swap_requests` table (real columns: `target_user_id`/`accepted_at`). Every attempt to create a swap threw a SQL error, and swap statistics silently under-counted the target side. Fixed in `EmployeeController`, `AdminSwapController`, the swap views, the dashboard, and `StoreStatsService`.
- `DELETE /api/v1/notifications/{id}` marked the notification as read instead of deleting it. `NotificationRepositoryInterface` gained a `delete()` method and the endpoint now actually deletes.
- `scripts/db-migrate.php --dry-run` was documented but never implemented — the script read no CLI arguments at all. It now lists pending migrations without applying them.
- `scripts/docker-setup.php` hashed the admin password with a different bcrypt cost than `install.php`/`provision.php`; aligned to cost 12.
- `.env.example` was missing several variables actually read via `env()` elsewhere (`DB_PREFIX`, `DB_CHARSET`, `DB_COLLATION`, `DB_DRIVER`, `SESSION_NAME`, `SESSION_LIFETIME`, `SESSION_SECURE`, `SESSION_HTTPONLY`, `SESSION_SAMESITE`, `APP_NAME`, `APP_VERSION`); added with their real defaults.

## [0.0.3-beta] - 2026-07-08

### Added
- **Initial public beta.** Full shift scheduling (list/calendar/week/day/Gantt timeline, drag & drop, bulk actions, print, overlap-conflict detection, open shifts + shift bidding, Excel import with visual analysis and confidence scoring); time & attendance (clock-in/out with live timer, admin editing, automatic wage estimation); employee self-service (leave requests, shift swaps, weekly availabilities, iCal feed, feedback widget); internal threaded messaging with live (SSE) updates and a notification center; daily KPI reports with a draft → submitted → validated workflow, PDF export (CJK-safe), scheduled auto-validation and email delivery; a versioned REST API (`/api/v1`, Bearer auth, pagination) covering every resource; one-click self-update from GitHub Releases with progress tracking and automatic backup/rollback; SQLite and MySQL support via a single, driver-agnostic Eloquent migration system; FR/EN/JA translations.
